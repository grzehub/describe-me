Troubleshooting

packages/core/src/types.ts · manifest-diagnostics.ts · recorder.ts · packages/vitest/src/print-diagnostics.ts · plugin.ts · reporter.ts · packages/viewer/cli/run-build.ts · print-vendor-report.ts

After every run describe-me lists what it could not document. This page explains each item, the warnings it prints once, and the symptoms people run into most.

Diagnostics after a run #

When a run ends, the reporter writes the manifest and prints what it could not document, one line per kind. Setup warnings come first, one line each, because they can explain failing tests. A line names at most 5 items and sums up the rest as (+n more). When everything is fine, it prints nothing.

The viewer shows the same list behind an "issues" chip in its header, with links to the tests. See Viewer and CLI. In this repository, pnpm check-manifest fails on any of them in the examples.

Key Console line What it means and how to fix it
anonymous describe-me: 2 tests render an anonymous component; export it from a project module or give it a displayName The component a test renders has no usable name, so the test is documented under Anonymous. Export the component from a project module, which names it after its export, or give it a displayName. See Naming.
undocumented describe-me: 3 components have no props docs: Card, Menu, Tabs The reporter could not read the props of these named components. Host elements such as div never count. Check that the component is exported from a TypeScript module and that typescript is installed. See Props.
assetsMissing describe-me: 1 asset was not found in the project and will not load in the viewer: /logo.svg A snapshot points at a file that is neither under the project root nor in public/, so the viewer cannot load it. Put the file where the path points. See Assets.
fontsMissing describe-me: 1 font family is used but never loaded: Inter (12 tests) — add it to previewHead The captured CSS uses the family, but no @font-face rule or font stylesheet loads it, in the frames or in the preview head. A family installed only on your machine counts as missing too. Load it in previewHead. See Fonts and the font check.
remoteStylesheets describe-me: frames load stylesheets from 1 remote host, which the viewer fetches from the network: use.typekit.net (8 frames) Frames link stylesheets from these hosts, so the viewer loads them from the network. Links in the preview head do not count here. Put font links in previewHead, and let describe-me build download what it can. See Vendoring.
setupWarnings describe-me: styled-components 6.1.8 resolves tslib 2.4.1, which has no tslib.es6.mjs, so its browser build may fail to load … The plugin found a problem in your setup that can make tests fail. The only one today: the browser build of styled-components with a tslib older than 2.5.3. Upgrade styled-components to 6.1.10 or later, or override tslib to 2.5.3 or later. See styled-components.

One-off warnings #

These lines show up once, when their cause does. None of them stops the run. Errors that do are under Symptoms and fixes.

Plugin and setup file

Warning When What to do
`test.css` is false, so imported stylesheets are stubbed … When Vitest starts, in a DOM environment whose config sets test.css: false. Remove the setting. The plugin then turns CSS on. See What the plugin changes.
using the browser build of styled-components, for createGlobalStyle When Vitest starts, in a DOM environment with styled-components 5 or later. It is information, not a warning. Nothing. See styled-components for why.
concurrent tests are not recorded (src/Menu.test.tsx) Once per test file that has concurrent tests. Concurrent tests would share one recorder, so they run but record nothing. Make them sequential to record them. See Environments.

Reporter

Warning When What to do
previewHead contains a <script>, which the viewer never runs. When Vitest starts. Remove the script. Load fonts with <link> or <style>. See Fonts.
include is an empty list, so no test file is recorded. … When Vitest starts, with include: []. Leave include out to record every test file, or use exclude: '**' to record none without the warning. See Which tests record.
the font audit failed: … At the end of a run, when the font check throws. The manifest gets empty fontsMissing and remoteStylesheets lists, so those diagnostics may miss something. Please report it with the message.
typescript is not installed, component props will not be documented At the end of a run where a recorded test rendered a component and typescript cannot be imported. Before 0.5.2 it also showed on runs that recorded no component. Install typescript as a dev dependency. See Installation.
[describe-me] could not read props of Card from src/Card.tsx At the end of a run, once per component whose props type it cannot find. Give the export a props type TypeScript can read. The component shows up under undocumented. See Props.
[describe-me] two components are named Card: src/a/Card.tsx and src/b/Card.tsx. Only the first is documented. At the end of a run, once per name, when two files export the same name. Props docs are keyed by name. Rename one of the exports. See Naming.

Recorder

Warning When What to do
renderFrame.pending is not a valid CSS selector: "…". Render frames fall back to 'lazy'. Once per test file, when the setup file configures the recorder. Fix the selector. Until then render frames are taken as with 'lazy'. See Render frame timing.

describe-me build

Warning When What to do
font vendoring stopped (…). Fonts keep loading from the network. When downloading the fonts fails as a whole. The build still finishes. Build again with network access, or pass --no-vendor-fonts. See Vendoring.
remote stylesheet hosts were not counted again (…). The issues menu keeps the list from the test run. After the build downloaded fonts and could not count the hosts again. The issues chip of the built site may still list hosts whose fonts were downloaded. See remoteStylesheets.
left remote: use.typekit.net (Adobe Fonts do not allow self-hosting) For each host the build does not download from: Adobe Fonts, hosts not on its allowlist, or any host once the 100 MB font budget is used up. Nothing, if the site may load them from the network. Otherwise host the font files in your project. See Vendoring.
… did not download (…). It keeps loading from the network., then and n more that did not download. For each stylesheet or font file that failed, the first 5 of them. Check the network and build again. Downloads are cached, so a later build fetches only what is missing. See Vendoring.

Viewer

Warning When What to do
style chunk styles/<hash>.css did not load In the browser console, when a stylesheet chunk fails twice. The frame shows with a gap in its styles, and the chunk is fetched again next time. Deploy the whole data directory, styles/ included. See Hosting.

Symptoms and fixes #

Symptom Cause Fix
Buttons look like browser defaults and text is in Times. Global styles, such as a reset or a body font, are missing. Render them in the wrapper of your custom render. See Global styles.
Cannot destructure property '__extends' when a test loads styled-components. The browser build of styled-components with a tslib older than 2.5.3. Upgrade styled-components to 6.1.10 or later, or override tslib to 2.5.3 or later. styledComponentsBrowserBuild: false also avoids it, but drops global styles from the snapshots. See styled-components.
Every test file fails with "all describe-me packages must be on the same version". Two copies of @describe-me/core at different versions, such as a 0.5.1 core next to 0.5.2 packages. Install all four packages at one version. See One version for all packages.
"cannot resolve @describe-me/react (the recording replacement for …). Install @describe-me/react." The adapter package is not installed. Install it. See Packages.
"include and exclude expect non-empty glob strings" or "renderFrame expects …" before any test runs. An option has a value the plugin does not accept. Fix the option. See include and Render frame timing.
The viewer shows "no manifest yet — run vitest first". No test run has written data yet, or --data points elsewhere. Run the tests, or pass the output directory with --data. See Viewer and CLI.
A built site opened from disk shows a blank page or "no manifest yet". The viewer fetches its data, which needs HTTP. Serve the folder over HTTP. See Hosting and the limitation.
A banner under the viewer header says the data comes from another version. The tests ran with another describe-me release line than the viewer. Install every package at the same version. See Viewer and CLI and Upgrading.
A popover sits in the top-left corner (jsdom). jsdom has no layout, so the library positions it at zero. Record such tests in browser mode. See Limitations in jsdom.
A test is missing from the sidebar. It recorded no frame before the closing one, it rendered outside the recording render, include or exclude leave it out, it is concurrent, or test.projects roots disagree on the path. Call step() to keep a test, or fix the globs. See Tests that are left out and Which tests record.
A component shows as Anonymous. It has no export name and no displayName. Export it from a project module. See Naming.
Fonts are missing in the viewer. Nothing in the frames or the preview head loads them. Load them in previewHead. See Fonts and fontsMissing.
Vite fails on the Node version. Vite 8 needs Node ^20.19.0 || >=22.12.0. Upgrade Node. See Node.
More act warnings with describe-me than without, in jsdom. On 0.5.1 the recorder waited with React's act flag on. Fixed in 0.5.2. On 0.5.1, upgrade all packages. To compare runs, use the same reporter in both, because minimal hides what passing tests print. See the limitation.
Fewer act warnings with describe-me than without, in jsdom. On 0.5.2 every user-event frame waited one macrotask with React's act flag off. Fixed in 0.5.3. On 0.5.2, upgrade all packages. Compare runs with the same reporter. See the limitation.
Vitest's console output differs with the plugin: no minimal or agent reporter in an AI agent session, no github-actions annotations. On 0.5.1 the plugin replaced Vitest's default reporters. Fixed in 0.5.2. On 0.5.1, name your reporters in the config. See the limitation and Reporters.
include: [] records every test file. On 0.5.1 an empty list meant every file. Fixed in 0.5.2, where it records none and warns. On 0.5.1, use exclude: '**'. See the limitation and Which tests record.

Reporting a bug #

Open an issue on GitHub. These make it quick to reproduce:

  • The versions of @describe-me/core, @describe-me/react, @describe-me/vitest and describe-me, of Vitest, Vite, React and the testing library, and of Node.
  • The generator field of .describe-me/manifest.json.
  • Browser mode or jsdom.
  • The console output of the run.
  • A minimal reproduction: a component, a test and the Vitest config.
