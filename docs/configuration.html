Configuration

packages/vitest/src/plugin.ts · reporter.ts · default-reporters.ts

One plugin line is the whole integration. This page lists what the plugin changes in your Vitest config, every option it takes, and how to wire describe-me by hand.

What the plugin changes #

describeMe() from @describe-me/vitest/plugin is a Vite plugin with enforce: 'pre', so its render redirect runs before other plugins resolve the import. It adds config through Vite's config hook, which Vite merges with yours. With enabled: false it adds nothing, and its resolveId and transform hooks do nothing: the plugin stays in the list but is inert.

Always

  • The environment. The environment option, else browser when test.browser.enabled is set, else dom. See Environments.
  • test.provide. It checks include, exclude and renderFrame, and hands them to the setup file under the key describe-me. Vite deep-merges provide, so your own keys stay. Invalid values throw before any test runs.
  • The reporter. It adds its reporter, which writes the output directory, next to yours or next to Vitest's defaults. See Reporters.
  • The render redirect. Its resolveId hook sends imports of vitest-browser-react (browser mode) or @testing-library/react (DOM) to @describe-me/react or @describe-me/react/testing-library. Imports from inside the adapter are left alone. When the adapter cannot be resolved, the import fails with an install hint, because the original module would record nothing. See How it works.
  • The export registration. A transform hook that runs after the TypeScript and JSX transforms appends a call that registers the top-level exports of your own script modules. A component is then named after its export, also when it is an anonymous forwardRef, memo or styled component. It skips test files, node_modules, virtual modules, module ids with a query and files outside the root. It runs only while Vite serves, which Vitest always does, so a vite build that shares the config is untouched. On a parse error it steps aside. registerExports: false turns it off. See Writing stories.

Browser mode

  • test.setupFiles: @describe-me/vitest/setup.
  • optimizeDeps.include: @describe-me/react and vitest-browser-react. Vite's dependency scan runs before the redirect and never sees the adapter. Without this, Vite finds it mid-run, optimizes again and reloads.

DOM

  • test.setupFiles: @describe-me/vitest/setup-dom.
  • test.env.RTL_SKIP_AUTO_CLEANUP = 'true'. Testing Library would otherwise unmount in its own afterEach, before the closing frame is taken. describe-me unmounts after that frame instead.
  • test.css = true, unless you set test.css. Vitest stubs CSS imports by default, which would leave every imported stylesheet out of the snapshots. With test.css: false the plugin warns: 
describe-me: `test.css` is false, so imported stylesheets are stubbed and will be missing from the snapshots.

DOM with styled-components

When styled-components 5 or later is installed and styledComponentsBrowserBuild is not false, the plugin logs one line and adds three things: 

describe-me: using the browser build of styled-components, for createGlobalStyle
  • A resolve.alias from styled-components to its browser ES module build. The Node build's createGlobalStyle never inserts its CSS, so global resets and fonts would be missing.
  • For styled-components 6.0 to 6.3, a tslib alias to tslib.es6.mjs. When that file is missing, the reporter prints a setup warning instead.
  • test.deps.optimizer.client, enabled for styled-components, plus jest-styled-components when it is installed, so both share one instance.

Styles and fonts explains why.

Options #

describeMe() takes one object, DescribeMeOptions. Every option is optional.

Option Type Default Effect
enabled boolean true false runs the same tests without recording. The plugin stays inert (what it changes).
framework 'react' 'react' Which framework adapter replaces the test library's render.
environment 'browser' | 'dom' detected Where the tests run. browser when test.browser.enabled is set, dom otherwise (detection).
outDir string '.describe-me' Output directory, relative to the Vitest root. When you change it, pass the same directory to the CLI with --data (storage).
registerExports boolean true Name components after their export (naming).
styledComponentsBrowserBuild boolean true DOM only. Load the browser build of styled-components (styled-components).
include string | string[] every test file Test files to record. An empty list records none, with a warning (which tests record).
exclude string | string[] none Test files never to record. Wins over include (which tests record).
previewHead string none HTML the viewer adds to the start of the <head> of every replayed frame. It never reaches the test page (what is captured).
renderFrame 'eager' | 'lazy' |
{ pending, timeout? } 		'eager' When the render frame is taken (render frame timing).

vitest.config.ts

import { defineConfig } from 'vitest/config'
import react from '@vitejs/plugin-react'
import { describeMe } from '@describe-me/vitest/plugin'

export default defineConfig({
  plugins: [
    react(),
    describeMe({
      // document the components, not the slow integration suites
      include: 'src/components/**',
      exclude: ['**/*.integration.test.tsx'],
      // the loader the app's providers show until they are ready
      renderFrame: { pending: '[data-testid="app-loader"]' },
    }),
  ],
  test: { environment: 'jsdom' },
})

Which tests record #

include and exclude take a glob or a list of globs. They are matched with picomatch against the path of the test file relative to the Vitest root, dotfiles included. A leading ./ is ignored, and exclude wins over include.

Tests in other files still run and report as usual. They record nothing, and their modules leave the manifest, also those kept from an earlier run.

Setting Records Warns
include left out every test file no
include: [] no test file once, when Vitest starts
exclude: '**' nothing, with the plugin still on no
enabled: false nothing, with the plugin inert no

The warning for an empty include:

describe-me: include is an empty list, so no test file is recorded. Leave include out to record every test file, or set exclude: '**' to record none without this warning.

An empty string or anything other than a string throws before any test runs:

describe-me: include and exclude expect non-empty glob strings, got ''

Projects with their own root

With test.projects entries that set their own root, the two sides disagree on the path. The setup file matches against the path relative to the project root, the reporter against the path relative to the Vitest root. With include: 'src/**' and a project root of packages/app, a file records frames but its module is missing from the manifest. Use globs that start with **/, such as **/src/components/**, which match both forms, or leave include and exclude out.

Concurrent tests are never recorded, because they would share one recorder. See Environments.

Render frame timing #

A component behind async providers or data loading shows a loader first. The render frame is taken right after mount by default, so the docs show that loader, as in the jsdom example's AsyncGreeting. renderFrame takes the frame later:

renderFrame The render frame is taken
'eager' (default) right after mount
'lazy' right before the test's next interaction, or at the end of the test
{ pending, timeout? } as soon as nothing matches the CSS selector pending and the page shows content

Every render frame follows the option, rerender included. An interaction is a user event, fireEvent, step(), another render, rerender, unmount or cleanup.

pending watches the page with a MutationObserver. After timeout ms (default 2000) it stops watching, and the frame waits as in 'lazy'. An interaction that comes first takes the frame too. A pending selector the DOM rejects also falls back to 'lazy', with one warning per test file: 

describe-me: renderFrame.pending is not a valid CSS selector: "…". Render frames fall back to 'lazy'.

Any other value, such as an empty selector or a timeout that is not a number above 0, throws before any test runs.

In browser mode, await render() returns before a deferred frame is taken. Polling with expect.element is not an interaction, so the frame waits for the next one. To take it earlier, call recorder.flush(), which takes a deferred frame after one settle: 

import { expect, test } from 'vitest'
import { render } from 'vitest-browser-react'
import { recorder } from '@describe-me/vitest'
import { Profile } from './Profile'

test('shows the profile', async () => {
  const screen = await render(<Profile />)

  await expect.element(screen.getByText('Ada')).toBeVisible()
  await recorder.flush()
})

Reporters #

The plugin adds its reporter to the reporters of your run. Which others run depends on your config:

  • Your config sets test.reporters. The plugin adds only its own reporter, and Vite concatenates it with your list.
  • Your config sets none. Any list replaces the reporters Vitest picks on its own, so the plugin adds Vitest's defaults and then its own. On Vitest 5 it copies Vitest's list: minimal for AI agents, else default, plus github-actions in GitHub Actions. Vitest 4 exports no list, so the plugin rebuilds its rule: agent for AI agents on Vitest 4.1 and later, else default, plus github-actions when GITHUB_ACTIONS=true.

--reporter on the command line replaces the whole list, describe-me's reporter included, so that run writes no output. A run of the jsdom example with vitest run --reporter=dot on Vitest 5.0.1 left its manifest untouched. Name extra reporters in the config instead.

A config of its own #

To record only when you ask for it, keep the plugin out of vitest.config.ts and add it in a second config that extends the first:

vitest.describe-me.config.ts

import { defineConfig, mergeConfig } from 'vitest/config'
import { describeMe } from '@describe-me/vitest/plugin'
import base from './vitest.config'

export default mergeConfig(
  base,
  defineConfig({
    plugins: [describeMe()],
  }),
)
vitest run --config vitest.describe-me.config.ts

Your usual vitest runs stay free of describe-me, and only this run records. mergeConfig takes objects, so vitest.config.ts must export an object, not a function.

Without the plugin #

You can wire the pieces by hand: the setup file and the reporter, the default export of @describe-me/vitest/reporter. In browser mode:

vitest.config.ts

import { defineConfig } from 'vitest/config'
import { playwright } from '@vitest/browser-playwright'
import DescribeMeReporter from '@describe-me/vitest/reporter'

export default defineConfig({
  test: {
    setupFiles: ['@describe-me/vitest/setup'],
    reporters: ['default', new DescribeMeReporter()],
    browser: {
      enabled: true,
      provider: playwright(),
      instances: [{ browser: 'chromium' }],
    },
  },
})

Then import render from @describe-me/react instead of vitest-browser-react. For jsdom, use the DOM setup file, and set css: true and RTL_SKIP_AUTO_CLEANUP yourself:

vitest.config.ts

import { defineConfig } from 'vitest/config'
import DescribeMeReporter from '@describe-me/vitest/reporter'

export default defineConfig({
  test: {
    environment: 'jsdom',
    setupFiles: ['@describe-me/vitest/setup-dom'],
    reporters: ['default', new DescribeMeReporter()],
    css: true,
    env: { RTL_SKIP_AUTO_CLEANUP: 'true' },
  },
})

Then import render, fireEvent and cleanup from @describe-me/react/testing-library instead of @testing-library/react.

Reporter options

Option Default What it does
outDir '.describe-me' Output directory, relative to the Vitest root.
include every test file Test files whose modules appear in the manifest. An empty list warns.
exclude none Test files to leave out of the manifest. Wins over include.
previewHead none HTML the viewer adds to the start of every replayed frame's head.
setupWarnings none Problems in the project's setup. The plugin fills it.

A hand-wired setup records every test, because only the plugin passes include and exclude to the setup file. The reporter still leaves the other modules out of the manifest. renderFrame also reaches the setup file only through the plugin. Set it with recorder.configure() in a setup file of your own, listed after describe-me's:

describe-me-timing.ts

import { recorder } from '@describe-me/vitest'

recorder.configure({ renderFrame: 'lazy' })
setupFiles: ['@describe-me/vitest/setup-dom', './describe-me-timing.ts'],

What a hand-wired setup does not get from the plugin:

  • Vitest's default reporters. Name the reporters you want yourself.
  • The render redirect. Your tests import the adapter directly.
  • include, exclude and renderFrame in the setup file, and their checks before the run.
  • The export registration, so components may lose their export names.
  • The browser build of styled-components in jsdom.
  • In browser mode, optimizeDeps.include for the adapter. Add it yourself if Vite reloads mid-run.

Environment variables #

The CLI sets DESCRIBE_ME_DIR for the viewer. The other variables below are switches of this repository's examples. The describe-me packages read none of them. The examples' vitest.config.ts files read them, for benchmarks and checks, and BENCH_SKIP and ACT_PARITY work only in examples/react-jsdom. Set them inline for one run. There is no .env.

Variable Read by Effect
DESCRIBE_ME_DIR the viewer's Vite config in describe-me The data directory. describe-me dev and describe-me build set it. Pass --data instead of setting it.
DESCRIBE_ME both examples off runs the same tests with enabled: false. idle runs them with exclude: '**', writing to node_modules/.describe-me-idle.
BENCH_OUT both examples A file name. Replaces the console reporter with JSON per-test durations in that file.
BENCH_MICRO both examples Runs bench/ instead of src/.
BENCH_SKIP examples/react-jsdom With DESCRIBE_ME=idle, a list of css, styled and exports that switches those parts of the plugin off. The browser example throws when it is set.
ACT_PARITY examples/react-jsdom Runs act-parity/ instead of src/, with lazy render frames. eager takes render frames right away and adds act-parity/setup.ts, which loads Testing Library before describe-me's setup file. pnpm check-act-parity sets it.

The same switch in your own project:

vitest.config.ts

import { describeMe } from '@describe-me/vitest/plugin'

describeMe({ enabled: process.env.DESCRIBE_ME !== 'off' })

An idle variant keeps the plugin on and records nothing. Its run writes an empty manifest and deletes the snapshots no frame points at, so give it a scratch directory: 

const idle = process.env.DESCRIBE_ME === 'idle'

describeMe({
  enabled: process.env.DESCRIBE_ME !== 'off',
  ...(idle ? { exclude: '**', outDir: 'node_modules/.describe-me-idle' } : {}),
})

Performance shows how to measure with these variants.
