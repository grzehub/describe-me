Limitations

packages/core/src/serialize-document.ts · materialize-adopted-styles.ts · packages/react/src/record-sync-action.ts · packages/vitest/src/register-recording-hooks.ts · packages/viewer/src/data.ts

describe-me is a prototype. This page lists every known limit, where it applies, the workaround and whether a fix is planned.

At a glance #

open has no fix announced. planned is on the roadmap. by design follows from how describe-me or the environment works. fixed in 0.5.2 names the release with the fix.

Limitation Applies to Workaround Status
fireEvent inside your own act() records before React flushes, so its frame shows the DOM from before the update. See Limitations in jsdom. jsdom Drop your own act(), because Testing Library already wraps fireEvent in one. Where the act() has to stay, put the block in a step(). open
Concurrent tests are never recorded, because they would share one recorder. See Environments. both Make the tests you want in the docs sequential. by design
States such as :hover or :focus-visible are not part of the DOM, so no snapshot holds them. See Environments. both A state shows when the component puts it into the DOM, for example as a class or an attribute. by design
A wrapper that ignores children never mounts your element, so the test gets no component name. See Naming. both Call recorder.setComponent() with name and file after render. planned
With test.projects entries that set their own root, include and exclude match different paths in the test run and in the reporter. See Which tests record. both Use globs that start with **/, or leave include and exclude out. open
A test skipped in a filtered run (-t, .only, .skip) keeps what the last run recorded for it. See Tests that are left out. both Run the whole suite before you publish the docs. by design
Recording adds time to every recorded test and to the end of the run. See Performance. both Record fewer files, or record in a docs run of its own. open
All four describe-me packages must be on one version. Mixed copies of @describe-me/core fail every test file. See One version for all packages. both Upgrade them together, and group them in your update bot. by design
Recording added React act warnings in jsdom. See Troubleshooting. jsdom On 0.5.1, upgrade all packages. fixed in 0.5.2
Recording hid React act warnings from updates that landed right after a user-event call. See Troubleshooting. jsdom On 0.5.2, upgrade all packages. fixed in 0.5.3
A wait of the recorder can move a React act warning in either direction. It waits for a held-back render frame at the end of a test, before the closing frame, after a step() and after a user-event call without @testing-library/react. See jsdom. jsdom Await findBy… or waitFor for async updates instead of a bare sleep. by design
The plugin replaced Vitest's default reporters, such as minimal for AI agents and github-actions. See Reporters. both On 0.5.1, name your reporters in the config. fixed in 0.5.2
include: [] recorded every test file. See Which tests record. both On 0.5.1, use exclude: '**' to record none. fixed in 0.5.2
Tooltips, menus and dropdowns placed by a positioning library show up in the top-left corner. See Limitations in jsdom. jsdom Record such tests in browser mode, or leave their files out with exclude. by design
What the test measures, scrolls or observes behaves differently, because jsdom has no layout. See Limitations in jsdom. jsdom Record such tests in browser mode. by design
Web fonts never load during the test, and a link that a font loader adds sets a timer in every capture. See Limitations in jsdom. jsdom Load fonts in previewHead, and do not call font loaders in tests. by design
Snapshots hold no canvas pixels, so a <canvas> is blank in the viewer. See Limitations in jsdom. both None. by design
adoptedStyleSheets on a shadow root are not captured. See Styling techniques. browser mode jsdom None yet. planned
jsdom has no constructable stylesheets, so document.adoptedStyleSheets cannot be captured. See Styling techniques. jsdom Record such components in browser mode. by design
Rules go through jsdom's CSS parser, which drops what it does not understand. Nesting, @layer and @container are not verified. See Styling techniques. jsdom Record such styles in browser mode. open
CSS linked from previewHead is copied as it is on disk, without PostCSS, Tailwind or any other Vite transform. See Fonts. viewer build Link plain CSS. open
The font check knows Google Fonts, Bunny Fonts and Fontsource on jsDelivr. A stylesheet from any other host turns it off, and a family installed only on your machine counts as missing. See The font check. build Load fonts from one of those hosts or with @font-face. open
describe-me build needs the network to download web fonts into the site. See Vendoring. build After one online build the font cache lets later builds run offline. --no-vendor-fonts keeps the build off the network. by design
The viewer replays recorded snapshots. It cannot mount a component live or change its props. See What comes next. viewer Write a test for each state you want to show. planned
A built site opened from disk does not load, because the viewer fetches its data. See Hosting. build Serve the folder over HTTP. open
A 0.4 viewer cannot read 0.5 data. Its frames show without their stylesheets. See Upgrading. viewer Upgrade describe-me together with @describe-me/vitest. by design

Recording #

A frame is the DOM at one moment, so what is not in the DOM is not in the frame: pseudo-class states and a fireEvent that React has not flushed yet. Concurrent tests and tests a filtered run skips record nothing new. A wrapper that ignores children needs you to name the test, and projects with their own root need **/ globs. Recording costs time, see Performance, and needs one version of every package. 0.5.2 fixed act warnings, the default reporters and an empty include. Writing stories explains which tests are left out.

Environments #

jsdom has no layout engine and loads nothing, so what differs is what happens inside the test: popovers, layout and observers and fonts. The frames are the same kind of thing in both environments, laid out by a real browser in the viewer. No snapshot holds canvas pixels. Environments has the details, and when to pick browser mode.

Styles and fonts #

A snapshot is DOM plus stylesheets, so styles that live elsewhere are missing: stylesheets adopted by a shadow root, and in jsdom every adopted stylesheet and rules its parser drops. The preview head skips Vite transforms, the font check knows three hosts, and font vendoring needs the network. Styles and fonts has the details.

Viewer and static site #

The viewer replays recorded snapshots. It does not run your components. A built site needs HTTP. A 0.4 viewer cannot read 0.5 data, and links to a test break when it is renamed. Viewer and CLI has the details.

Frameworks and tools #

describe-me is a prototype. It works with React only: the core has no React in it, but React is the only adapter. It records Vitest tests only, in browser mode or jsdom. Vue and Svelte adapters are on the roadmap. No other test runner is announced.

What comes next #

These are announced, without dates:

  • Controls. Turn the props table into inputs and mount the component live, in development only, through a playground endpoint on the Vitest server.
  • Live mount. Run a test again up to a given frame inside the viewer, with hot module reload.
  • adoptedStyleSheets in shadow roots. Capture them as the document's are.
  • Vue and Svelte adapters. A render wrapper each.
  • Names from wrappers that ignore children. Today you name such a test with recorder.setComponent().
