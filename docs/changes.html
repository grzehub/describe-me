Comparing runs

describe-me diff compares two runs of your tests and lists what changed. It reports and never fails.

A base run #

The command reads two data directories that the reporter wrote: the base, a run from before a change, and the current run. Two things keep the comparison honest:

  • Run the whole suite on both sides. A filtered run keeps the entries of the tests it skipped from the run before, so they would compare as unchanged.
  • Compare the directories the reporter wrote, never the __data/ of a built site. describe-me build rewrites the snapshots in its copy when it downloads fonts.

Locally, keep a copy of the data from before the change:

  1. Before the change Run the tests, then copy their output: cp -r .describe-me .describe-me-base.
  2. After the change Run the tests again.
  3. Compare npx describe-me diff --base .describe-me-base.

Keep the copy out of git, as the data directory itself:

.gitignore

.describe-me
.describe-me-base

The shadcn/ui example records a second run of its tests with SHADCN_CHANGED=1, and pnpm check-diff compares the two.

The command # 

describe-me diff --base <dir> [--data .describe-me]
                 [--out <dir> [--shots] [--width 480] [--max-shots 20] [--root <dir>]]

--base is the run to compare against, --data the current run. --shots and its flags add before and after images. The flags are in Viewer and CLI.

  • Without --out it prints a summary and writes no file: one sentence with the counts, the tests whose DOM or state changed by file, the changed props, the added, removed and moved tests, and how many tests changed only in CSS.
  • With --out <dir> it writes changes.json and changes.md there and prints the sentence and where the files went. It creates the directory when it is missing and never empties it.
  • With --out <dir> --shots it also writes an image of each test that looks different (before and after images).
  • The exit code is 0 whenever it could compare, whatever changed. There is no threshold and no flag that turns a change into a failure.

It exits with code 1 only without --base, when it cannot read a run, or with --shots when a flag is out of range or Playwright or its Chromium is missing. It writes nothing then and prints one of these, with the paths as you typed them: 

describe-me: diff needs --base <dir>, the data directory of the run to compare against
describe-me: no manifest at .describe-me-base/manifest.json
describe-me: cannot read .describe-me/manifest.json: not valid JSON
describe-me: .describe-me/manifest.json is not a describe-me manifest
describe-me: cannot read .describe-me/snapshots/3f2a9c1d0b7e4a55.json
describe-me: .describe-me/manifest.json names a snapshot outside .describe-me
describe-me: --shots needs --out <dir>, where the images go
describe-me: --width needs a whole number of CSS pixels from 200 to 1920, got "abc"
describe-me: --max-shots needs a whole number from 0, got "x"
describe-me: --shots needs Playwright, and cannot find it from /projects/app. Run npm install -D playwright and npx playwright install chromium in the project, or pass --root with a project that has it.
describe-me: cannot start Chromium for --shots (browserType.launch: Executable doesn't exist at …). Run npx playwright install chromium in the project.

What counts as a change #

Tests match by their id, which comes from the file, the suite path and the name. A manifest written before 0.5 gets the same ids. A test in both runs is changed when its snapshots or its state differ. A test in one run only is added or removed.

Moved is a removed and an added test with exactly the same snapshots in the same order, such as a renamed test or one moved to another file. A moved test whose CSS changed as well shows as removed and added. Tests without frames never pair.

Frames match by content. Snapshot files are named after their content, so a frame with the same name is unchanged. The frames between them pair by their DOM, so one step added in the middle of a test is one added frame, also when a new class changed the global stylesheet of every frame.

Kind What changed
dom The serialized DOM, with the stylesheet text left out. That includes attributes such as class and style, the hover and focus states of a frame, links, and the content names of images and other assets, so a swapped image is a dom change. A test is dom when one of its frames is, or when a frame was added or removed.
css Only the stylesheet text. One new Tailwind class changes the global sheet, so every frame changes its name, and the tests that do not use the class are css. changes.md folds them.

A state change, such as passed to failed with the same frames, is a change of its own and shows with the DOM changes. Labels, timings, meta, tags, errors and the rendered component are no change.

Props count for the components in both runs: a prop added or removed, or with another type, another default, or now required or optional. Descriptions do not count. A component in one run only is not listed, because its tests show as added or removed. The props come from the component files as they were when the tests ran.

Versions. When the manifests name different versions of @describe-me/vitest, or only one names its version, the report says so. Some changes may then come from the update rather than from your code.

changes.json and changes.md #

changes.json holds the whole report. Its paths are relative to each run's directory, so it names no machine. These are its fields:

Field What it holds
version 1. A later release may add fields to version 1, never remove or change one.
base The generator and generatedAt of the base's manifest. generator is absent for a manifest written before 0.5.1.
head The same for the current run.
versionsDiffer true when the manifests name different versions, or only one names its version.
counts tests: changed, and of those dom and css, then added, removed, moved and unchanged. frames: the same without moved, every frame of an added or removed test included.
tests One entry per changed, added and moved test in the order of the current run, then the removed tests in the order of the base. Each has its change, id, module and fullName, a kind when its frames changed, a state when its state did, from when it moved, and its changed, added and removed frames with their index, label and snapshot on each side. With --shots, each changed frame has a look, same or different, absent when a side did not render. A changed test has look different when one of its frames does, and same when all of them do and no frame was added or removed. A test with an image has shot: the file in --out and the index of the frame it shows in the current run.
components The components whose props changed, by name, each with its props: name, change, and the type, whether it is required and the default on each side.
shots Only with --shots: the width of the frames in CSS pixels, their pixelRatio, maxShots, how many distinct pairs of changed frames it compared, how many of them look different (differentPairs) or have a side that did not render (failedPairs), and how many images it wrote.

changes.md is the body of a pull request comment. It starts with the line <!-- describe-me:changes -->, by which a workflow can find its earlier comment, and the sentence with the counts. Then come the version note, the sections Changed, Props, Added, Removed and Moved, and last the tests that changed only in CSS, folded. With --shots the section Looks different comes first, with the images, and the folded tests are the CSS-only ones that look the same (the three groups). Names from the manifest are in code spans, so a test name cannot mention anyone or render HTML. The file stays within GitHub's limit of 65,536 characters. When the lists do not fit, each is cut and ends with - and N more. A shortened sample:

changes.md

<!-- describe-me:changes -->

16 of 16 tests changed (6 only in CSS).

### Changed

`src/components/ui/button.test.tsx`

- `Button > renders the default variant`: 1 frame changed
- `Button > highlights a ghost button on hover`: 2 frames changed

`src/components/ui/feedback.test.tsx`

- `Badge > renders every variant`: 1 frame changed

<details><summary>6 tests changed only in CSS</summary>

`src/components/ui/form-controls.test.tsx`

- `Input > renders a placeholder`: 1 frame changed

</details>

Before and after images #

With --shots the command renders every changed frame before and after in headless Chromium and compares the pixels. It needs --out, where the images go: 

npx describe-me diff --base .describe-me-base --out changes --shots

It takes Playwright from your project, so playwright is an optional peer dependency of describe-me and only --shots needs it. Install it and its Chromium once: 

npm install -D playwright
npx playwright install chromium

It looks for Playwright from the project root that the current run's manifest names. --root <dir> names another project, such as one in browser mode next to your jsdom project. Playwright and Chromium start only when there is something to render.

How a frame renders

  • From the stored snapshot, through the viewer's own replay code, on a bare page of the viewer on a Vite dev server. Frames render only in describe-me diff, never in a test run.
  • In Chromium, in the light color scheme, --width CSS pixels wide (480 by default) at twice the pixel density.
  • At its natural height, measured as the viewer measures it, up to 1600 CSS pixels. Content that fills the viewport gets 720.
  • After its fonts and images loaded, with transitions off, CSS animations finished and the text caret hidden. A font or stylesheet that failed to load does not stop the frame, but the command warns, because the pair may differ for that alone.

The images and the three groups

A pair of changed frames looks different when a single pixel differs. There is no threshold. A test looks different when one of its pairs does, and gets one PNG in --out, <test id>.png. It shows the first such pair in three panels: before, after, and the changed pixels over a dimmed copy of after. Each changed pixel is marked with a few around it, so a change of one pixel still shows when GitHub scales the image down. An added test gets its first render frame alone. A removed or moved test gets none. changes.md then sorts the changed tests into three groups:

  • Looks different comes first, each test with its image.
  • Changed keeps the tests whose DOM changed but look the same, without an image, and the tests with a frame that did not render.
  • The tests that changed only in CSS and look the same are folded last.

--max-shots caps the images, 20 by default. The tests that look different take them first, in the order of the report, then the added tests. The rest stay listed by name, and the section says how many have no image. --max-shots 0 compares and writes no image. --width takes 200 to 1920 CSS pixels.

--out is never emptied, so images of an earlier run stay there, and changes.md shows only the ones of this run. Nothing else is written: no file next to the viewer, in either data directory or in a temp directory. A frame that does not render gets a warning on stderr, and its pair no look. A shortened sample:

changes.md

<!-- describe-me:changes -->

16 of 16 tests changed (6 only in CSS). 10 of the changed tests look different.

### Looks different

`src/components/ui/button.test.tsx`

- `Button > renders the default variant`: 1 frame changed, 1 looks different

  ![frame 1: before, after and the changed pixels](./e5e1c5cf428e.png)

<details><summary>6 tests changed only in CSS and look the same</summary>

`src/components/ui/form-controls.test.tsx`

- `Input > renders a placeholder`: 1 frame changed

</details>

What it does not see #

Without --shots it compares the recorded DOM and stylesheet text, not pixels, so a CSS change that renders the same is still listed, folded with the other CSS-only tests. With --shots it compares pixels too, and only folds the CSS-only tests that paint the same, in Chromium only, in the light scheme only and at one width. Either way it does not see:

  • what a <canvas> draws, because snapshots hold no canvas pixels
  • an image, font or stylesheet that another host serves and changes under the same URL
  • the preview head and foundations.json. A frame renders with the preview head of its own run, but a change of the head alone changes no frame, so no frame is rendered for it.

It is no gate: there are no thresholds, approvals or baselines in the repository. For visual regression testing as a gate, use a visual testing tool.
