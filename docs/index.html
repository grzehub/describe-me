Your tests are your stories

README.md · packages/vitest/src/plugin.ts · packages/core/src/compact-frames.ts · packages/viewer/cli/main.ts

describe-me records the DOM after every step of your component tests and shows the frames as browsable documentation. There are no stories to write and nothing to keep in sync.

How it fits together #

Four packages share the work:

  • @describe-me/core: the recorder, step() and the manifest types. The other packages depend on it, so you do not add it yourself.
  • @describe-me/react: the recording render, for vitest-browser-react and for @testing-library/react.
  • @describe-me/vitest: the Vitest plugin, the setup files and the reporter.
  • describe-me: the viewer and its CLI.

How it works follows a frame from the test to the viewer.

What you get #

Stories from tests

Every describe is a group and every it a story. There is no separate story abstraction.

A frame for every step

Frames after render, after each interaction and after each step(), on a timeline you can scrub.

Component overview

Props read from TypeScript, and which of their values your tests cover.

Diagnostics

What could not be documented, such as anonymous components or missing assets, in the terminal and in the viewer.

A static site

describe-me build writes a site you can host anywhere.

See it in the examples #

Browser mode

Buttons, a counter, a menu and a search box, recorded in Chromium through Vitest browser mode.

jsdom

A design-system style suite with Testing Library, user-event and styled-components, recorded in jsdom.

Examples describes both projects. The viewers need the built site, which pnpm site serves locally, and do not open from disk. Open the viewers explains why.

What it does not do yet #

  • React only. The core is framework-agnostic, but React is the only adapter.
  • Static snapshots. There is no live mount and there are no controls.
  • jsdom has no layout and loads no fonts inside the test. See Limitations in jsdom.
  • Pseudo-class states such as :hover or :focus-visible are not in the DOM, so no frame shows them.

Limitations lists every known limit.
