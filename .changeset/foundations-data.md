The reporter writes the design-system foundations of the project to `foundations.json` next to `manifest.json`. It lists the design systems that `package.json` and `components.json` name (Tailwind, shadcn/ui, Material UI, Chakra UI, Mantine, Radix Themes, styled-components, Emotion, Ant Design), the recorded stylesheets that declare custom properties on `:root`, `:host`, `html`, `.dark`, `.light` or `[data-*]`, and the stylesheets with `@font-face`. It also holds the Tailwind 4 theme, each token marked `project` or `default`. The option `foundations: { theme: 'src/theme.ts' }` (or `'src/theme.ts#name'`) adds the tokens of a Material UI theme or a plain theme object, with `light-dark()` values split into light and dark. `foundations: false` switches it off, and `DescribeMeReporterOptions` takes the same option. The manifest has an optional `foundations` field with the systems, the token count and the problems. `manifestDiagnostics()` returns the problems as `foundationsErrors`, which the terminal and the viewer's diagnostics menu show. `foundationsErrors` is a new required member of `ManifestDiagnostics`, so code that builds a `ManifestDiagnostics` object itself has to add it. `@describe-me/core/types` exports `Foundations`, `FoundationsSheet`, `FoundationsSystem`, `FoundationToken`, `FoundationGroup`, `FoundationTokenType`, `DesignSystemId` and `ManifestFoundations`. When `describe-me build` vendors fonts, it points the copied `foundations.json` at the moved style chunks.
